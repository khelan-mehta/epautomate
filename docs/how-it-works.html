What is epAutomate?

epAutomate is a zero-dependency energy-model data pipeline that reads raw DOE-2.2 .SIM output files (and optional .inp input files) and produces a formatted .xlsx workbook — replacing the manual 30-column lookup process required for LEED / ASHRAE 90.1 Appendix G submittals.

It ships in two deployment modes: a Python CLI (server or analyst workstation) and a pure HTML/JS single-page app that runs entirely in the browser with no server, no Python, no install.

Output Discrepancies vs. Target Workbook

Comparison of epAutomate's .xlsx output against the reference Book1.xlsx template reveals the following gaps. All other fields are present and populated.

▲
Above Ground East Wall Area (ft²) — column appears twice in the reference sheet (.1 suffix variant). epAutomate writes directional wall areas as zero; per-facade wall breakdown (N/E/S/W) requires parsing LV-C surface azimuths, which is not yet implemented. The aggregate Gross Wall Area is correct.
▲
Vertical Weighted R-Value (ft²·h·F/Btu) — the inverse of Vertical Weighted U-Value is computed and written, but the reference workbook carries a standalone column that may expect a separately-sourced assembly R-value rather than the derived 1/U. Values should match when U is the correct combined assembly U.

All 135+ other columns map 1:1 and populate from .SIM / .inp parsing. Fields not available in simulation output (carbon factors, district energy rates) are intentionally written as 0 and can be filled via a config JSON.

Generic Multi-Engine Architecture

To support multiple simulation engines, epAutomate will evolve toward a normalized JSON intermediate schema, decoupling engine-specific parsing from the Excel output layer.

JSON Schema Design Goals

  • Flat key-value dict, one row per simulation run
  • All values in SI-adjacent imperial (kBtu, ft², W)
  • Null for fields not provided by engine (not 0)
  • Engine name and file path stamped on every record
  • Versioned schema tag for forward compatibility

Parser Registry Pattern

  • Each engine registers a parser class implementing parse(file) → dict
  • CLI / UI detects engine from file extension or user selection
  • Single excel_writer consumes any normalized dict
  • LLM-assisted field mapping for engines with non-standard headers (future)
