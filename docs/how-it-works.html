What problem does this solve?

DOE-2.2 (eQUEST) emits results as plain-text .SIM files — roughly 130,000 lines per run, organized into ~50 numbered reports. Energy modelers manually copy values from these reports into Excel comparison sheets for LEED, ASHRAE 90.1, and code-compliance submittals. A single project produces 8+ baseline rotations plus a proposed design, meaning nearly 1,000 manual lookups per submittal cycle.

epautomate reads each .SIM file, locates the relevant report sections, extracts ~120 metrics, and writes a fully formatted Excel workbook with BL Data and Proposed Data tabs in seconds.

Two ways to invoke it

CLI   ad-hoc runs

python sim_extractor/run.py \
  --bl baseline_0.SIM baseline_90.SIM \
  --proposed proposed.SIM \
  --option "LEED Baseline" \
  --output results.xlsx

Config   reproducible batch

{
  "runs": [
    {"sim_file": "sim/baseline_0.SIM",
     "tab": "bl",
     "option_name": "LEED Baseline"},
    {"sim_file": "sim/proposed.SIM",
     "tab": "proposed",
     "option_name": "Proposed Design"}
  ],
  "output": "results.xlsx",
  "rates": { "electricity_per_kbtu": 0.0425 }
}

Parsing strategy

Each SIM report begins with a marker line like REPORT- PS-B Utility and Fuel Use Summary. The parser:

  1. Locates the section by scanning for its REPORT- XX-Y marker.
  2. Reads forward to the next REPORT- line (or to a known end-of-section sentinel like =======).
  3. Splits fixed-width columns using whitespace tokenization — DOE-2 uses column-aligned text, never tabs.
  4. Handles continuation pages: many reports break across pages with a (CONTINUED) header — the parser stitches them back together before splitting.
  5. Sums across instances for per-system reports (SS-R, SV-A): walks every occurrence and totals the relevant columns.

Excel output formatting

  • Two sheets: BL Data (baseline runs) and Proposed Data (proposed designs).
  • Color-coded headers by category: blue=ID, green=energy, orange=end-use, teal=peaks, lime=geometry, red=systems.
  • Frozen top row + frozen first column so you can scroll the wide table without losing context.
  • Number formats applied: integers for kBtu totals, 2-decimal for intensities, percentages for WWR.
  • Append-friendly: re-running with new SIM files adds rows to existing sheets when --output points to an existing file.

What is not in the SIM file

A handful of Excel columns can't come from the .SIM output because they are either user policy or BDL input parameters that DOE-2.2 doesn't echo: climate zone, utility rates, carbon emission factors, and external shading type descriptors. These are read from the --config JSON (under rates / climate_zone) and applied during aggregation.

Extending the parser

Add a new metric

  1. Find which REPORT- contains it.
  2. Add a _parse_xxx() method to SIMParser returning a dict.
  3. Call it from parse() and merge into the result.
  4. Add the column name to excel_writer.COLUMNS with its category color.

Add a new tab

  1. Add the tab key to SHEET_NAMES in excel_writer.py.
  2. In run.py, add a CLI flag (e.g. --asbuilt).
  3. Tag runs with "tab": "asbuilt" in config.
Tip: For interactive exploration of the column-to-SIM-report mapping, open sim_excel_mapping.html in any browser. It contains a hoverable, searchable table of all 120+ columns and the exact report each one comes from.
